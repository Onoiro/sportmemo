# Проверка semver перед коммитом

## Где живёт версия

Единственный источник истины — **`pyproject.toml`**, секция `[project] version`.
Оттуда её читает `config/settings.py` (через `tomllib`) и отдаёт в шаблоны как
`SPORTMEMO_VERSION` (контекстный процессор `apps.core.context_processors.project_info`).

После изменения версии **обязательно** выполнить:

```bash
uv lock
```

`uv.lock` содержит версию корневого проекта — без синхронизации CI (`uv sync --frozen`)
упадёт.

## Как определить тип бампа

Посмотрите изменения:

```bash
git status && git diff HEAD
```

| Тип | Когда | Примеры |
|---|---|---|
| **minor** | новые возможности, миграции схемы | новая модель или поле, новая админка, новый раздел UI |
| **patch** | исправления, UX, переводы | исправление бага, правка текстов, улучшение админки |
| **none** | документация, тесты, CI | README, KODA.md/AGENTS.md, новые тесты, workflow |

Правила для этого проекта:

- **Любая миграция схемы — минимум minor.** Схема данных публичного архива: изменение
  структуры — новая возможность, а не исправление.
- **Правки правил проекта** (KODA.md/AGENTS.md) — `none`, даже если файлы большие.
- **Новые тесты без изменения кода** — `none`.
- **CI и Makefile** — `none`, если не меняют поведение продукта.
- Если в одном коммите есть и фикс, и новая возможность — берите **старшую** категорию.

Пока проект не выпущен (версия `0.x`), счётчик ведётся как обычно: `0.1.0` → `0.2.0`
для новых возможностей, `0.1.0` → `0.1.1` для исправлений.

## Порядок действий

1. Посмотреть diff:
   ```bash
   git status && git diff HEAD
   ```
2. Определить тип бампа по таблице выше.
3. Если бамп нужен — обновить `version` в `pyproject.toml`.
4. Синхронизировать lock-файл:
   ```bash
   uv lock
   ```
5. Проверить, что версия читается:
   ```bash
   uv run python -c "import tomllib,pathlib; print(tomllib.loads(pathlib.Path('pyproject.toml').read_text())['project']['version'])"
   ```
6. Прогнать проверки перед коммитом (обязательно):
   ```bash
   make lint && make test
   ```
7. В сообщение коммита добавить строку:
   ```
   Bump version: 0.1.0 → 0.2.0 (minor)
   ```

## Язык сообщения коммита

Сообщение коммита пишется **на простом английском** — так, чтобы понял человек, для которого
английский не родной. Короткие предложения, простые слова, без идиом. Тело коммита объясняет
**почему** изменение нужно, а не перечисляет, что изменено.

## Пример сообщения коммита

```
feat: add photo model and admin page

Photos need a place in the database. This commit adds the Source, Photo
and PhotoPerson models. It also adds admin pages for them.

The original image is never overwritten. A processed copy goes into a
separate field. This keeps the original file safe.

Bump version: 0.1.0 → 0.2.0 (minor)
```

## Когда бамп не нужен

Если изменение попадает в категорию `none`, в сообщении коммита можно явно указать:

```
docs: describe the folder structure in README

Bump version: none (docs)
```

Это делает решение явным и избавляет от вопроса «а версию обновляли?».
