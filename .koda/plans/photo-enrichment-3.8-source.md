## 1. Цель и границы

**Цель.** Автор может сказать, откуда снимок, двумя простыми ответами — без справочника
из девяти полей и без ручной работы модератора. Свободный текст остаётся текстом:
`Source` **не создаётся автоматически никогда**. Структурный `Source` по-прежнему
заводит модератор в админке, когда структура оправдана (подшивка газеты на сотни фото).

**Что уже есть и используется:**

- `Source` (`apps/photos/models.py:70`): `kind`, `title`, `publication`, `date`, `page`,
  `url`, `holder`, `owner`, `notes`. Выводится на `/photos/<pk>/`
  (`templates/photos/photo_detail.html:80-97`).
- `PhotoDetailsForm` (`apps/photos/forms.py:232`): одна форма на шаг 2 и на правку.
- `_photo_edit_initial()` (`apps/photos/views.py:69`): начальные значения шага 2 —
  год из EXIF, `?team=` / `?event=`.
- `Photo._merge_relations()` (`apps/photos/models.py:420`): заполняет пустые поля
  канона при слиянии дубликатов — список полей придётся расширить.
- `PhotoAdmin.fieldsets` (`apps/photos/admin.py:152`), блок «Привязка».
- `BootstrapFormMixin` (`apps/core/forms.py:24`): классы полям.

**Что входит в подэтап:**

- `SourceOrigin` (`TextChoices`) и два поля на `Photo`: `source_origin`, `source_note`;
- правило вывода источника — в одном месте (`apps/photos/source.py`), шаблон
  печатает готовое;
- `initial` для источника из последнего фото **автора фото**;
- поля в форме шага 2 / правки, вывод на странице фото, поля в админке;
- перенос `source_origin` / `source_note` при слиянии дубликатов;
- тесты, локализация, документация, версия.

**Что не входит:**

| Отложено | Куда |
|---|---|
| Создание `Source` из введённого текста | **не делаем никогда** (решение 1 мастер-плана) |
| Поле «автор снимка» (фотограф ≠ владелец) | **P3-25**, вместе с 5.5 |
| Индексация `source_note` в поиске | не входит: в строке уточнения может быть чужое имя, и фото начнёт находиться по фамилии из чужого альбома |
| Редактор «Люди на фото» | **3.9** (P3-15) |
| Очередь людей | **3.10** (P3-26) |
| Правка источника модератором на сайте | админка остаётся площадкой модератора |

## 2. Решения

### 2.1 Пять вариантов происхождения

```python
class SourceOrigin(models.TextChoices):
    PERSONAL = "personal", _("из моего личного архива")
    OTHER_ARCHIVE = "other_archive", _("из архива другого человека")
    PRESS = "press", _("газета, журнал, книга")
    INTERNET = "internet", _("из интернета")
    UNKNOWN = "unknown", _("не знаю")
```

`default=""` и `blank=True`: пустая строка значит «не указано», и это **отличается**
от «не знаю». Первое — человек не заполнял, второе — осознанный ответ. Смешивать
нельзя: по пустому полю видно, что человек ещё не возвращался к фото.

### 2.2 Имя владельца личного архива не хранится

При `personal` подпись собирается из `photo.uploaded_by.display_name`; при `None`
(анонимизация по P5-12) — нейтральное «Из личного архива автора». Причина —
в мастер-плане 2.1: имя, положенное текстом, переживёт «удаление аккаунта».

`source_note` остаётся свободным для настоящего уточнения происхождения
(«архив тренера Сидорова»): это описание архива, а не атрибуция аккаунта,
и оно законно остаётся после анонимизации.

### 2.3 Правило вывода — `apps/photos/source.py`

Шаблон не сравнивает поля. Функция отдаёт готовый dataclass или `None`:

```python
@dataclass(frozen=True)
class SourceDisplay:
    origin_label: str   # «Из моего личного архива»
    holder: str         # «Сергей Иванов» или пусто
    note: str           # уточнение или пусто
```

```python
def source_display(photo) -> SourceDisplay | None:
    """Что показать в блоке «Источник». `None` — показывать нечего."""
```

Порядок: привязан `Source` → `None` (шаблон выводит существующий подробный блок);
иначе пустой `source_origin` → `None`; иначе подпись варианта, `holder` только
для `personal`, `note` как есть.

Почему отдельный модуль, а не свойство модели: подпись `holder` требует
`uploaded_by`, и `select_related` удобнее ставить в представлении; в модели это
дало бы скрытый запрос на каждое обращение к свойству в списках.

### 2.4 `initial` — из последнего фото автора

Человек, оцифровывающий альбом на 60 снимков, вводит источник один раз.

- Автор берётся **у фото**, а не у текущего пользователя: модератор правит чужое
  фото и не должен подставлять свой источник.
- Подсказка не подставляется, если у фото уже есть `source` или `source_origin`:
  заполненное поле не перетирается.
- Берётся последнее по `created_at` фото того же автора с непустым `source_origin`;
  подставляются оба значения — человек их видит и может изменить.
- `uploaded_by` пуст (аккаунт анонимизирован) → подсказки нет.

Функция — в `apps/photos/services.py`, рядом с `can_edit_photo`:

```python
def recent_source(photo) -> dict:
    """Происхождение из последнего фото того же автора или пустой словарь."""
```

### 2.5 Порядок полей в форме

Объявленные в классе поля идут первыми, поэтому итоговый порядок:
`team_name`, `event_name`, `title`, `caption`, `year`, `taken_date`,
**`source_origin`**, **`source_note`**. Источник — в конце: это дополнительный
вопрос, а не главный.

`source_note` показывается всегда, а не только при выборе «не мой архив»:
скрытие по выбору требует JavaScript, а без него подсказка менялась бы не у всех.
Один `help_text` покрывает оба случая: «Например: архив И. Иванова или Советский
спорт, 1994».

### 2.6 Слияние дубликатов

`_merge_relations()` уже заполняет пустые `source_id`/`year`/`team_id`/`event_id`/
`taken_date` канона. Добавляются `source_origin` и `source_note` — по тому же
правилу «заполнить пустое, не перетирая». Без этого слияние теряло бы данные,
которые человек ввёл.

### 2.7 Что не меняется

- `Source` и его админка — как есть.
- Публичная выдача, `public`, поиск, карта сайта, кабинет — не меняются.
- Права: правит автор и модератор, проверка уже есть в `can_edit_photo`.
- `rights_confirmed` не возвращается в правило видимости.

## 4. Риски и как их снимаем

| Риск | Что делаем |
|---|---|
| Модератор правит чужое фото и подставляет свой источник | `recent_source()` берёт автора **фото**, а не пользователя; тест на это |
| Заполненное поле перетирается подсказкой | Подсказка только при пустых `source` и `source_origin` |
| Слияние теряет введённое происхождение | Расширяем `_merge_relations()` в том же подэтапе |
| Подписи вариантов разъедутся между шаблоном и админкой | Подписи берутся из `SourceOrigin` (`get_source_origin_display()`), второй словарь не заводим |
| Пустое и «не знаю» смешиваются | `default=""` отдельно от `unknown`; тест на оба состояния |
