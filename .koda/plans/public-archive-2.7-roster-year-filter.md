# SportMemo — Этап 2.7: фильтр состава команды по годам

Дата создания: 2026-10-11
Статус: **завершён**
Мастер-план этапа: [`public-archive.md`](public-archive.md)
Предыдущий подэтап: [`public-archive-2.6-person-photo-pages.md`](public-archive-2.6-person-photo-pages.md)
Версия на старте: 0.6.0
Ветка: `feature/roster-year-filter`

---

## 1. Зачем это и почему не «состав по годам»

Изначально 2.7 планировался как отдельная страница `/teams/<slug>/roster/` —
«состав команды по годам». От этой формулировки **отказались по решению владельца
(2026-10-11)**.

Причина: архив наполняется по чужим альбомам и газетным вырезкам, и на старте состав
за любой год будет заведомо неполным — один-два известных человека из пятнадцати.
Страница «Состав команды 1994 года» в такой ситуации врёт читателю: он прочитает её
как полный список. Обещать полноту мы не можем.

Поэтому в 2.7 делаем **фильтр по годам на существующей странице команды**. Разница
принципиальная: фильтр — это «уточнить список известных людей», а не «показать полный
состав». Отдельная страница с группировкой по годам вернётся позже — когда составов
наберётся столько, что группировка станет осмысленной (идея I-8 в бэклоге).

**Что не делаем в этом подэтапе:**

| Не делаем | Куда |
|---|---|
| Отдельная страница `/teams/<slug>/roster/` с группировкой по годам | идея I-8 в бэклоге |
| Фильтр по роли (игрок / тренер / …) | не нужен при малом объёме данных |
| Пагинация состава | состав команды — не галерея, список короткий |
| Поиск по людям | 2.12, 2.13 |

---

## 2. Принятые решения

Согласовано с владельцем 2026-10-11.

| # | Вопрос | Решение |
|---|---|---|
| В-1 | Незакрытый период (`year_from` есть, `year_to` пуст — в демо-данных таких около четверти) | Считать человека в команде **до последнего года, известного по этой команде** (`fallback_year`): максимум среди `year_from`/`year_to` всех её членств и годов её событий. Иначе он либо «размазался» бы на все годы до 2010, либо не попал бы никуда, кроме года начала |
| В-2 | Формулировка | Заголовок блока — «Люди в команде, 1994 год», под списком — подпись «В архиве указаны не все, кто играл». Слова «полный состав» и «состав года» не используем |
| В-3 | Лимит | Режим «все годы» — превью 12 человек (`TEAM_ROSTER_PREVIEW`) и счётчик всего состава; выбранный год — **полный** список (иначе фильтр бессмыслен: отфильтровали и не увидели) |

Решения, принятые при составлении плана (владелец их не оспаривал):

| # | Вопрос | Решение |
|---|---|---|
| В-4 | Только `year_to` (`year_from` пуст) | Человек попадает **только** в год `year_to` (последний известный год в команде) и в блок «год не указан». Утверждать, что он играл в более ранние годы, нельзя |
| В-5 | Ни `year_from`, ни `year_to` | Человек виден только в режиме «все годы» с подписью «год не указан»; в селект годов он не добавляет ни одного года. Отдельного блока «год не указан» не делаем: режим «все годы» — тот же плоский список, что и сейчас, а второй список людей на той же странице только запутал бы |
| В-6 | Два членства одного человека в одном году (игрок + тренер) | Две строки (как сейчас на странице команды) — объединение ролей не делаем: строки различаются ролью, годами и амплуа |
| В-7 | Сортировка отфильтрованного списка | Роль (тренер → руководитель → персонал → игрок), затем фамилия и имя. Сортировка модели (`-year_from`) при фильтре по году смысла не имеет |
| В-8 | Невалидный `?year=` | Если год не входит в список доступных — фильтр считается неприменённым (показываем все годы). Симметрично мягкой пагинации: опечатка в ссылке не даёт пустую страницу |
| В-9 | Блок состава при отсутствии членств | Не рендерится целиком — ни списка, ни формы фильтра (тест `test_minimal_team_has_no_empty_sections` уже это проверяет) |

Действующие решения мастер-плана:

- Черновик в публичном UI виден автору и модератору (с плашкой «Не опубликовано»), остальным —
  404. Работает готовый `get_visible_or_404()`.
- Люди в публичном контексте — только через `Person.public.published()` и `Person.public_name`.
- Все строки интерфейса — через `gettext`, `make i18n` после добавления строк.

## 3. Что должно получиться на экране

**`/teams/sokoly/`** (фильтр не применён). Блок «Состав» как сейчас: до 12 человек,
рядом — счётчик «всего 34 человека» и форма фильтра: `<select name="year">` со списком
годов (от новых к старым, первый пункт — «Все годы») и кнопка «Показать». Ниже —
подпись «В архиве указаны не все, кто играл».

**`/teams/sokoly/?year=1994`**. Заголовок — «Люди в команде, 1994 год». Полный список
людей, чей период в команде накрывает 1994 год: имя ссылкой, роль, годы, амплуа, номер.
Селект показывает выбранный год. Рядом — ссылка «Показать все годы» (сбрасывает фильтр).

**Открытый период.** Человек с `year_from=1992` и пустым `year_to` в команде, где последний
известный год — 1998, попадает в 1992–1998. В 1999 году его уже нет.

**Пусто и вырожденно.** Нет членств — блока состава нет вообще. Все членства без годов —
селект не рендерится (нет ни одного года), список идёт как «год не указан».

**Черновик команды.** Автор и модератор видят страницу с плашкой и работающим фильтром;
остальные получают 404.

### 3. [x] Модуль группировки `apps/catalog/roster.py`

- Навыки: koda-coder
- Файлы:
  - `apps/catalog/roster.py` (новый)
- Содержание: чистые функции без обращений к базе — вся логика периодов в одном месте,
  чтобы её можно было проверить unit-тестами без запросов.

  ```python
  ROLE_ORDER = {Role.COACH: 0, Role.MANAGER: 1, Role.STAFF: 2, Role.PLAYER: 3}

  def membership_bounds(membership, fallback_year) -> tuple[int | None, int | None]
  def roster_years(memberships, *, fallback_year=None) -> list[int]   # от новых к старым
  def memberships_in_year(memberships, year, *, fallback_year=None) -> list
  def sort_key(membership) -> tuple
  ```

  - `membership_bounds` — решения В-1, В-4, В-5: `(None, None)` при пустых годах;
    `(year_from, year_to or fallback_year or year_from)` при заполненном `year_from`;
    `(None, year_to)` при одном `year_to`.
  - `roster_years` — объединение диапазонов, от новых к старым; годы, в которые не попадает
    ни один человек, не появляются.
  - `memberships_in_year` — пересечение диапазона с годом; сортировка по В-7.
  - `sort_key` — `(ROLE_ORDER[role], person.last_name, person.first_name, year_from)`.
    Порядок ролей держим рядом с логикой, а не в шаблоне: та же сортировка нужна тестам.
- Проверка: `uv run python -c` на нескольких членствах; полное покрытие — в шаге 8.

## 5. Критерии готовности подэтапа

1. На странице команды есть фильтр по годам; состояние живёт в URL; форма работает
   без JavaScript.
2. Список годов — от новых к старым, только годы, в которые попадает хотя бы один
   известный человек.
3. Открытый период (`year_to` пуст) заканчивается последним годом, известным по команде;
   человек с одним `year_to` попадает только в этот год.
4. Режим «все годы» показывает превью 12 человек и счётчик; выбранный год — полный список.
5. Формулировки не обещают полноты: «Люди в команде, 1994 год» и подпись о неполноте архива.
6. Люди без годов видны в режиме «все годы» с подписью «год не указан» и не добавляют
   годов в селект.
7. Черновик человека и скрытая фамилия не попадают в выдачу ни в одном режиме.
8. Нет членств — нет блока состава и формы; нет годов — нет селекта.
9. `make lint && make test` зелёные, `makemigrations --check` чист; обе темы и ~375 px
   не разъезжаются.
10. README, KODA.md, AGENTS.md описывают новое состояние; мастер-план и бэклог поправлены;
    версия 0.7.0, `uv.lock` синхронизирован.

## 6. Риски и заметки

| # | Риск | Как учитываем |
|---|---|---|
| R-1 | Читатель принимает список за полный состав года | Формулировка «Люди в команде, 1994 год» + подпись «В архиве указаны не все, кто играл» (решение В-2) |
| R-2 | Открытый период «размазывает» человека на все годы | Верхняя граница — `fallback_year` (решение В-1); значение считается из членств и событий команды |
| R-3 | `fallback_year` у команды без событий и без закрытых периодов | Верхняя граница падает до года начала членства — человек попадает в один год; крайний случай покрыт тестом |
| R-4 | Черновик человека попадает в отфильтрованный список | Фильтр `Person.public.published()` применяется до среза и до фильтрации по годам |
| R-5 | Срез `[:12]` до фильтрации по году | Срез делается последним: сначала фильтр публичности и года, потом срез по режиму |
| R-6 | Селект с десятками годов | Годы команды ограничены её историей; при росте списка вернёмся к группировке (идея I-8) |
| R-7 | `makemessages` ставит `fuzzy` на новые строки | Проверка fuzzy-блоков после `make i18n` |
| R-8 | Смена формата годов в превью ломает тесты страницы команды | Формат `years_label` совпадает с прежним текстом шаблона; тесты проверяют вхождение подстрок, а не разметку |
| R-9 | Фильтр утекает в индексацию поисковиками | `noindex` для страниц с query-параметрами — в 2.10 |

Отклонения от плана и решения по ходу работы:

1. **Отдельного блока «год не указан» нет.** Планировалось выводить людей без годов отдельным
   списком, но это второй список людей на той же странице — только запутало бы. Люди без годов
   видны в режиме «все годы» с подписью `years_label` = «год не указан» и не добавляют годов
   в фильтр (решение В-5 уточнено, план обновлён).
2. **`split_roster()` не понадобился** — после отказа от отдельного блока функция осталась
   бы мёртвым кодом и была удалена из модуля.
3. **Срез превью делается в представлении, а не в queryset.** `team_memberships()` отдаёт
   весь список: какой режим показать, решает представление, и срез не должен стоять до
   фильтрации по году.
4. **Юнит-тесты `roster.py` создают объекты без сохранения** (`TeamMembership(year_from=...)`).
   `sort_key` обращается к `person.last_name`, поэтому человек задаётся явно
   (`Person(first_name=...)`) — иначе обратная связь падает на незаполненном FK.
