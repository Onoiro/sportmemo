# SportMemo — Этап 2.6: страницы человека и фотографии

Дата создания: 2026-10-11
Статус: **завершён**
Мастер-план этапа: [`public-archive.md`](public-archive.md)
Предыдущий подэтап: [`public-archive-2.5-team-event-pages.md`](public-archive-2.5-team-event-pages.md)
Версия на старте: 0.5.0
Ветка: `feature/person-photo-pages`

## 1. Зачем это

Страницы команд и событий готовы (2.5), но два конца архива ещё не связаны:

1. **Люди.** `Person.url_name = "catalog:person_detail"` уже указывает на маршрут, которого нет.
   Из-за этого состав команды выводится текстом без ссылок, а «Люди на фото» на странице фото —
   просто список имён. Архив не даёт ответа на главный вопрос: «кто этот человек и где он ещё
   снят?»
2. **Фотография.** Страница фото существует с 2.4, но ссылки на людей с неё не ведут.
   С 2.6 фото становится «единицей архива»: с него можно перейти к каждому человеку в кадре
   и увидеть все остальные кадры с ним.

2.6 закрывает и главный риск проекта — **приватность несовершеннолетних**. До сих пор
`name_visibility` проверялась только в списках: на отдельной странице человека легко случайно
вывести `display_name` (в котором лежит полная фамилия) в заголовке, в `<title>`, в крошках
или в вариантах имён. Здесь это правило становится явным и покрывается тестами.

**Что не делаем в этом подэтапе:**

| Не делаем | Куда |
|---|---|
| Полный «состав по годам» команды (`/teams/<slug>/roster/`) | 2.7 |
| Ссылка «это я» и связь `User.person` в UI | 2.8 |
| Метатеги, Open Graph, JSON-LD (кроме аккуратного `title`/`description`) | 2.10, 2.11 |
| Поиск по людям | 2.12, 2.13 |
| Комментарии под страницей человека | 2.14 |
| Отдельный каталог `/people/` | не планируется (решение № 6 мастер-плана) |

## 2. Принятые решения

Согласовано с владельцем 2026-10-11 (ответы на вопросы плана).

| # | Вопрос | Решение |
|---|---|---|
| В-1 | Показывать ли варианты имён (`PersonName`) | **Только при `name_visibility = full`.** При `first_name_only` и `hidden` блок «Также известен как» не рендерится: прозвище или «фамилия при рождении» раскрыли бы скрытую фамилию |
| В-2 | Откуда брать главное фото | `Person.avatar`, если он **видим** (`Photo.is_public`); иначе — самое свежее видимое фото, где человек отмечен (`PHOTO_ORDERING`). Если фото нет — заглушка-иконка |
| В-3 | Биография | **Показывать как есть.** Текст вводит автор, ответственность за упоминание фамилий — на модераторе (риск R-3) |
| В-4 | Страница человека со `name_visibility = hidden` | **Открывается** с нейтральной подписью «Имя не указано». Скрывать страницу нельзя: иначе фото и команды потеряли бы связь с человеком |
| В-5 | Список команд на странице человека | Один список «Команды и роли» (команда, роль, годы, амплуа, номер), без группировки по годам — группировка в 2.7. Ссылка на команду — только если опубликована |

Решения мастер-плана, действующие здесь:

- Черновик в публичном UI виден автору и модератору (с плашкой «Не опубликовано»), остальным —
  404. Работает готовый `get_visible_or_404()` из 2.3.
- Ссылка на неопубликованную сущность не создаётся: название выводится текстом.
- Люди в публичном контексте выводятся через `Person.public_name`, никогда через `display_name`.
- Маршруты с `SlugModel` используют конвертер `uslug` (`apps/core/converters.py`), не `<slug:...>`.
- Все строки интерфейса — через `gettext`, `make i18n` после добавления строк.
- `QueryDict` для ссылок галереи собирается через `gallery_filter()`, а не склейкой строки.

## 3. Что должно получиться на экране

**`/people/gromov-aleksey/`.** Крошки «Главная → Алексей Громов». Шапка: главное фото (или
заглушка), `h1` — публичное имя, под ним годы жизни («1955 — 2019», «род. 1958», «ум. 2008» —
или ничего). Ниже — плашка модерации (для черновика у автора), биография, атрибуты,
«Команды и роли» (Соколы — тренер, 1983–1989, амплуа), «Фотографии» (галерея с «показать
ещё»), «Также известен как» (только при полном имени).

**`/people/kirill-prohorov/`** (`first_name_only`). Заголовок — «Кирилл». Фамилии нет нигде:
ни в `h1`, ни в `<title>`, ни в крошках, ни в блоке имён (блок не рендерится).

**`/people/yudin-stanislav/`** (`hidden`). Заголовок — «Имя не указано». Фото, команды и
биография на месте — страница открывается, связи не теряются.

**`/photos/<pk>/`.** В блоке «Люди на фото» имя человека — ссылкой на его страницу, если
человек опубликован; черновик — текстом.

**`/teams/sokoly/`.** В составе имена — ссылками на страницы людей (состав и так отфильтрован
по `Person.public.published()`, поэтому человек всегда опубликован).

**Черновик человека.** Автор и модератор видят страницу с плашкой «Не опубликовано»;
остальные получают 404.

**Общее.** Всё открывается анонимно, работает в сепии и в тёмной теме, не разъезжается
на ~375 px. Пустые блоки (нет фото, нет команд, нет биографии, нет атрибутов) страницу
не ломают и не оставляют пустых заголовков.

- Содержание: булево свойство рядом с `public_name`:

  ```python
  @property
  def is_full_name_public(self) -> bool:
      """Можно ли раскрывать полное имя (и варианты имён)."""
      return self.name_visibility == NameVisibility.FULL
  ```

  Нужно шаблону: правило «варианты имён только при полном имени» должно жить рядом

### 3. [x] Представление `person_detail` и маршрут `catalog:person_detail`

- Навыки: koda-coder
- Файлы:
  - `apps/catalog/views.py`
  - `apps/catalog/urls.py`
- Содержание:
  - `person_detail(request, slug)` (`@require_GET`):
    1. `person = get_visible_or_404(Person, request=request, slug=slug)` — черновик, скрытое,
       отклонённое, удалённое и слитое отсеивает готовый хелпер.
    2. Перечитать объект с `select_related("avatar")`: хелпер отдаёт объект без предвыборки,
       иначе шаблон сделает отдельный запрос за главным фото.
    3. **Главное фото** (решение В-2): `person.avatar`, если он видим
       (`person.avatar_id and person.avatar.is_public`); иначе —
       `visible_photos().filter(photo_persons__person=person).order_by(*PHOTO_ORDERING).first()`.
       Ничего не нашлось — `hero_photo = None`, шаблон покажет заглушку.
    4. **Галерея**: `visible_photos().filter(photo_persons__person=person)
       .select_related("team", "event")`, `paginate(request, qs.order_by(*PHOTO_ORDERING),
       PHOTO_PAGE_SIZE)`, в контекст — `gallery_query=gallery_filter(person=person.slug)`.
       Фильтр `person` во фрагменте `photos:grid` уже поддержан (2.4) — фрагмент не меняем.
       Главное фото из галереи не исключаем: фрагмент про него не знает, а исключение
       сдвинуло бы пагинацию и «показать ещё».
    5. **Команды и роли**: `person.memberships.select_related("team")`, порядок
       `F("year_from").desc(nulls_last=True)`, `"team__name"`. Команда-черновик остаётся
       в списке: название выводится текстом, ссылки не будет.
    6. **Варианты имён**: `person.names.all()` — но только при `person.is_full_name_public`.
       Скрывать на уровне представления, а не шаблона: правило приватности не должно
       зависеть от того, какой шаблон отрендерился.
    7. `attribute_items(person.attributes)`.
    8. `breadcrumbs`: Главная → `person.public_name`.
  - `apps/catalog/urls.py`: `path("people/<uslug:slug>/", views.person_detail,
    name="person_detail")`.
- Проверка: `manage.py check`; на демо-данных `/people/gromov-aleksey/`,
  `/people/kirill-prohorov/`, `/people/yudin-stanislav/` отвечают 200; кириллический slug

## 5. Критерии готовности подэтапа

1. `/people/<slug>/` открывается анонимно, отдаёт 404 черновику постороннему и открывается
   автору и модератору с плашкой «Не опубликовано».
2. При `first_name_only` и `hidden` фамилия не встречается в HTML ни в одном месте:
   ни в `h1`, ни в `<title>`, ни в крошках, ни в вариантах имён.
3. При `hidden` страница открывается с нейтральной подписью, фото и команды сохраняются.
4. Главное фото выбирается по правилу В-2; невидимый `avatar` не показывается.
5. Ссылки на людей появились в составе команды и в блоке «Люди на фото»; ссылок на
   неопубликованных людей нет.
6. Пустые блоки не ломают вёрстку и не оставляют пустых заголовков.
7. `make lint && make test` зелёные, `makemigrations --check` чист; обе темы и ~375 px
   не разъезжаются.
8. README, KODA.md, AGENTS.md описывают новое состояние; версия 0.6.0, `uv.lock`
   синхронизирован.

## 6. Риски и заметки

| # | Риск | Как учитываем |
|---|---|---|
| R-1 | Фамилия утекает в `title`, крошки или `og`-теги | `title` и `description` строятся только из `public_name`; тест ищет фамилию по всему телу ответа |
| R-2 | `display_name` содержит полную фамилию (заполняется в `Person.save()`) | В шаблонах используется только `public_name`; `{{ person }}` тоже возвращает `public_name` |
| R-3 | Биография содержит фамилию несовершеннолетнего | Решение В-3: показываем как есть; ответственность на модераторе. Отметить в KODA.md как известное ограничение |
| R-4 | Варианты имён (`PersonName`) раскрывают скрытую фамилию | Блок рендерится только при `name_visibility = full`; скрытие делается в представлении, не в шаблоне |
| R-5 | Главное фото — командный снимок, лицо неразличимо | Осознанное ограничение данных: распознавание лиц — не этот этап. Главное фото выбирает модератор через `Person.avatar`; `avatar` без прав игнорируется |
| R-6 | Главное фото дублируется в галерее | Принято: исключение сдвинуло бы пагинацию, а фрагмент `photos:grid` про аватар не знает |
| R-7 | Ссылка на человека-черновика | В составе команды черновиков нет (фильтр `Person.public.published()`); в «Людях на фото» ссылка создаётся только при `is_published` |
| R-8 | `Person.avatar` — FK на фото без `select_related` | Объект перечитывается с `select_related("avatar")` один раз |
| R-9 | Маршрут `people/<slug>/` конфликтует с другими | Префикс `people/` уникален; список `/people/` не создаём |
| R-10 | `makemessages` ставит `fuzzy` на новые строки | Проверка fuzzy-блоков после `make i18n` |
| R-11 | Черновик человека утекает в поисковики | `noindex` для черновиков — в 2.10 |

Отклонения от плана и решения по ходу работы:

1. **Описание страницы (`description`) зависит от видимости имени.** Именная фраза
   «Человек Имя не указано в архиве SportMemo.» при `hidden` читалась бы как ошибка, поэтому
   при неполном имени подставляется общее описание сайта (та же строка, что в `base.html`).
2. **В шапке используется `thumbnail`, а не `preview`**: превью 1280 px для аватара 200 px
   избыточно. Ширина и высота заданы явно, чтобы вёрстка не прыгала.
3. **Тесты страницы человека не используют фикстуру `person` из `conftest.py`**: та создаёт
   черновик. В файле объявлены свои фикстуры `person` (опубликован) и `draft_person` —
   так доступ и приватность проверяются без лишнего `publish()` в каждом тесте.
4. **`name_variants` — пустой список, а не `QuerySet.none()`**: шаблон проверяет
   `{% if name_variants %}`, а тесты — равенство `[]`; запрос к базе при скрытом имени
   не выполняется вовсе.
