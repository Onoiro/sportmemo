## 1. Цель и границы этапа

**Цель.** Сделать архив доступным публике: серверный рендеринг страниц команд, событий, людей
и фотографий, галереи, поиск, регистрация и вход, комментарии — всё для SEO и для людей,
пришедших по ссылке из мессенджера.

**Что входит в этап:**

- каркас публичного UI (layout, тема, навигация, главная);
- списки и страницы-детали (команда, событие, человек, фото, годы);
- галереи с ленивой загрузкой и «показать ещё» на htmx;
- SEO: метатеги, Open Graph, sitemap, robots, Schema.org;
- поиск: `pg_trgm` + `tsvector`;
- регистрация, вход, подтверждение email, сброс пароля, профиль;
- создание команды пользователем (форма → `draft`);
- комментарии и жалобы;
- фильтры каталога.

**Что не входит (осознанно):**

| Отложено | Куда |
|---|---|
| Загрузка фото пользователем, превью в браузере | этап 3 (P3-1) |
| Обработка фото (OpenCV), Celery-пайплайн, `phash` | этап 3 |
| PWA, офлайн, установка на телефон | этап 4 |
| Юридические страницы, SMTP, деплой, бэкапы | этап 4 |
| API (DRF/django-ninja), SPA | не планируется, пока клиент один |

До этапа 3 контент попадает в базу через админку и через management-команду `seed_demo`
(подэтап 2.1).

### 3.3 Публичные выборки

Правило проекта: публичные выборки идут только через `public` (без удалённых и слитых объектов).
Дополняем его статусом публикации:

- `SoftDeleteQuerySet.published()` — фильтр `status=Status.PUBLISHED`; доступен моделям
  со `StatusModel`;
- `Photo` получает `visible()` — `status=published` **и** `rights_confirmed=True`
  (инвариант «фото без подтверждённых прав не публикуется»);
- хелпер `get_visible_or_404(model, *, request=None, **lookup)` в `apps/core/shortcuts.py`:
  отдаёт объект из `public`; неопубликованный объект отдаёт 404, кроме автора
  (`created_by` / `uploaded_by`) и модератора — им показывается с плашкой «не опубликовано».

### 3.4 Тема

Bootstrap 5.3 понимает только `data-bs-theme="light"` и `"dark"`. Сепия делается так:

- на `<html>` всегда стоит `data-bs-theme="light"` (или `"dark"`);
- светлая сепия — класс `theme-sepia`, переопределяющий переменные Bootstrap
  (`--bs-body-bg`, `--bs-body-color`, `--bs-secondary-bg`, `--bs-border-color`, ссылки и т. д.);
- выбор хранится в `localStorage.sportmemo-theme`, при первом визите берётся
  `prefers-color-scheme`;
- скрипт выбора темы вставляется инлайном в `<head>` **до** отрисовки, чтобы не было мигания;
- заголовки — serif-стек системных шрифтов (архивный вид), текст — системный sans; внешние
  шрифты не грузим.

### 3.5 Локализация

Все строки интерфейса — через `gettext`, каталоги `locale/ru` и `locale/en`.
`make i18n` после каждого подэтапа, добавляющего строки.

## 4. Сквозные правила подэтапов

1. **Поток работ** (по правилам проекта): задача из этого плана → ветка `feature/<короткое-имя>` →
   коммиты → `make lint && make test` → squash-merge в `master` → ветка удаляется.
   PR и GitHub issues не используем.
2. **Проверки перед коммитом:** `make lint && make test`. Для подэтапов с шаблонами —
   дополнительно ручная проверка страниц в браузере на `make run` (или Docker).
3. **Semver** — по навыку `semver-checker`. Ориентир: новые страницы и возможности — **minor**;
   исправления и UX — **patch**; документация, тесты, CI — **none**. После бампа — `uv lock`.
4. **Отметки в планах:** шаги подэтапа отмечаются `[ ]` → `[x]` в его файле плана, строка
   подэтапа — в разделе «Прогресс» этого файла.
5. **Тесты:** каждый подэтап добавляет тесты в `tests/` (представления — через `client`,
   публичность — через `public`/`published`, приватность — на `name_visibility`).
6. **Шаблоны:** наследуются от `base.html`; для тестов проверяем код ответа и ключевые элементы
   (заголовок, наличие объекта), а не точную вёрстку.

### 2.1 [x] Демо-данные для разработки

**Цель.** Наполнить базу вымышленным архивом, чтобы UI можно было смотреть и тестировать
без ручного ввода через админку.

**Объём.**

- Management-команда `python manage.py seed_demo` в `apps/core/management/commands/seed_demo.py`.
- Состав: 5 команд (разные города и годы основания), ~30 человек, 8 событий (1980–2010),
  ~40 фото, 6 источников, состав команд и люди на фото.
- Часть данных намеренно «неудобная»: 2–3 объекта в `draft`, люди со всеми тремя значениями
  `name_visibility`, фото без подтверждённых прав, события без даты.
- Изображения генерируются Pillow: фон-градиент в сепийных тонах, год и название команды
  текстом, разные пропорции (портрет, ландшафт, квадрат).
- Все демо-объекты помечаются `attributes={"demo": true}`; автор — пользователь
  `demo@sportmemo.ru`.
- Идемпотентность: повторный запуск не создаёт дублей (`update_or_create` по slug).
- Флаг `--flush` удаляет только демо-объекты (включая файлы изображений и демо-пользователя).
  Порядок удаления важен: `Photo.uploaded_by` — `PROTECT`, поэтому фото удаляются до пользователя.
- Флаг `--photos N` — сколько фото создать (по умолчанию 40).

**Файлы:**

- `apps/core/management/__init__.py`, `apps/core/management/commands/__init__.py`
- `apps/core/management/commands/seed_demo.py`
- `tests/test_seed_demo.py`
- `README.md` (раздел «Демо-данные»)

**Критерии готовности.**

- `make seed-demo` на пустой базе создаёт описанный набор за разумное время (< 1 мин).
- Повторный запуск не увеличивает количество объектов.
- `make seed-demo-flush` удаляет демо-объекты и файлы, не задевая обычные данные.
- Тесты: состав, идемпотентность, `--flush`, приватность (`hidden` не отдаёт фамилию).

**Навыки:** koda-coder, semver-checker. **Размер:** S. **Semver:** patch.

### 2.7 [x] Фильтр состава команды по годам

**Цель.** Уточнить список людей на странице команды: «кто известен по этому году».

**Изменение объёма (2026-10-11).** Изначально подэтап планировался как отдельная страница
`/teams/<slug>/roster/` с группировкой по годам. От этого отказались: архив наполняется
по чужим альбомам и вырезкам, и состав за конкретный год на старте будет заведомо неполным
(один-два известных человека из пятнадцати). Страница «Состав команды 1994 года» читалась бы
как полный список, а обещать полноту мы не можем. Вместо страницы — **фильтр по годам
на существующей странице команды**: это «уточнить список известных людей», а не «показать
полный состав». Отдельная страница вернётся, когда составов наберётся достаточно —
идея I-8 в бэклоге.

**Объём.**

- `?year=1994` на странице команды: форма GET с селектом годов (от новых к старым,
  первый пункт — «Все годы»); состояние живёт в URL, работает без JavaScript.
- Режим «все годы» — превью 12 человек и счётчик; выбранный год — полный список.
- Люди без годов (`year_from` и `year_to` пусты) видны в режиме «все годы» с подписью
  «год не указан» и не добавляют годов в фильтр: второй список людей на той же странице
  только запутал бы.
- Незакрытый период (`year_from` есть, `year_to` пуст) заканчивается последним годом,
  известным по команде (максимум по её членствам и событиям).
- Формулировки не обещают полноты: «Люди в команде, 1994 год» + подпись «В архиве указаны
  не все, кто играл».

**Файлы:** `apps/catalog/roster.py`, `apps/catalog/models.py`, `apps/catalog/views.py`,
`templates/catalog/team_detail.html`, `templates/catalog/partials/roster_form.html`,

`tests/test_team_roster.py`

**Критерии готовности.** Годы считаются верно, включая пересекающиеся и открытые периоды;
фильтр работает и живёт в URL; люди без годов не добавляют годов в фильтр и видны

**Навыки:** koda-coder, semver-checker. **Размер:** S. **Semver:** minor.

### 2.10 [x] Метатеги и Open Graph

**Цель.** Ссылка на любую страницу красиво разворачивается в мессенджерах и понятна поисковикам.

**Объём.**

**Файлы:** `templates/partials/meta.html`, `templates/partials/og_default.html`,
шаблоны страниц, `tests/test_meta_tags.py`

**Критерии готовности.** В исходном коде страницы есть корректные `og:title`, `og:description`,
`og:image` (абсолютный), `canonical`; черновик содержит `noindex`; тесты проверяют теги.

**Навыки:** koda-coder, semver-checker. **Размер:** S. **Semver:** minor.
**Детальный план:** [`public-archive-2.10-meta-tags.md`](public-archive-2.10-meta-tags.md)
(утверждён 2026-10-14; метатеги собираются во вьюхах через `page_meta()` в `apps/core/seo.py`).

**Итог (2026-10-15).** Метатеги собираются в Python: `page_meta()` (`apps/core/seo.py`) отдаёт
полный словарь `meta`, партиал `templates/partials/meta.html` только выводит значения.
Заглушка `og:image` — `static/img/og-default.png` (1200×630, сепия, генерируется Pillow,
адрес без хэша содержимого: мессенджеры кэшируют карточку). Дефолт процессора `seo_meta` —
`{"noindex": True}`, публичные вьюхи перекрывают его своим `meta`. `canonical` без параметра
`page`, `?page>1` → `noindex, follow`. Картинка: фото → `preview`, команда → `logo`,
человек → главное фото, остальные → заглушка. Приватность имени: `og:title` и описание
только из `public_name` при `first_name_only`/`hidden`. `noindex` у черновиков, поиска,
форм команды, «моих команд», профиля, страниц аккаунта, 404 и 500 (у 500 — прямо в шаблоне:
Django рендерит её без `request`, процессор не работает).
Тесты: `tests/test_meta_tags.py` (36), всего 636 (было 600).
Отклонения от плана: заглушка собирается через `settings.STATIC_URL`, а не `{% static %}`
(хэшированный адрес менялся бы после каждого деплоя); `noindex` для 500 добавлен в шаблон;
описание главной берётся общее, из `page_meta` (иначе английская локаль ловила русский текст
в тесте локализации).
Версия 0.11.0.

### 2.11 [x] sitemap, robots и Schema.org

**Цель.** Сайт нормально индексируется, а карточки получают расширенную выдачу.

**Объём.**

- `django.contrib.sitemaps`: `apps/core/sitemaps.py` — команды, события, люди, фото, главная;
  только опубликованное; `lastmod` из `updated_at`.
- `robots.txt` (шаблон) со ссылкой на sitemap; закрытые разделы в `Disallow`.
- JSON-LD: `WebSite` (с `SearchAction`), `SportsTeam`, `Person`, `SportsEvent`, `ImageObject`;
  фамилия несовершеннолетних в разметку не попадает.

**Файлы:** `apps/core/sitemaps.py`, `apps/core/schema.py`, `apps/core/templatetags/jsonld.py`,
`templates/robots.txt`, `templates/partials/jsonld.html`, `config/urls.py`, `config/settings.py`,
`tests/test_seo.py`

**Критерии готовности.** `/sitemap.xml` содержит только опубликованные объекты и валиден;
`/robots.txt` отдаёт корректный текст; JSON-LD проходит проверку синтаксиса, приватные имена
в него не попадают.

**Навыки:** koda-coder, semver-checker. **Размер:** S. **Semver:** minor.
**Детальный план:** [`public-archive-2.11-sitemap-robots-schema.md`](public-archive-2.11-sitemap-robots-schema.md)
(утверждён 2026-10-15; карта сайта — индекс + пять секций, домен из Sites, микроразметка
собирается в `apps/core/schema.py`, `BreadcrumbList` не делаем).

**Итог (2026-10-15).** Карта сайта — индекс `/sitemap.xml` и пять секций
(`pages`, `teams`, `events`, `people`, `photos`); выборки берутся из `apps/core/shortcuts.py`
и `public.published()`, поэтому черновики, скрытое, отклонённое, удалённое, слитое и фото
без подтверждённых прав в карту не попадают. Домен карты задаёт `django.contrib.sites`
(`sportmemo.ru`), схему — запрос: за сайтом стоит nginx, и адрес не должен зависеть
от настроек прокси. `robots.txt` отдаёт Django (`templates/robots.txt`), а не nginx:
список закрытых разделов и адрес карты лежат рядом с кодом. Микроразметка собирается
в Python (`apps/core/schema.py`) по тому же правилу, что метатеги: правило приватности имени
и выбор картинки живут в одном месте. Тег `{% jsonld %}` экранирует `<`, `>`, `&`,
U+2028 и U+2029 — название вида `</script>` не ломает страницу. Отклонение от мастер-плана:
один партиал `templates/partials/jsonld.html` вместо папки `jsonld/*.html` — данные и так
собираются в Python, пять шаблонов с одним и тем же `<script>` не нужны. `django.contrib.sitemaps`
добавлено в `INSTALLED_APPS` ради штатных шаблонов пакета. Годы жизни в разметку не выводим:
в модели только год, а `birthDate` по стандарту — дата. Тесты: `tests/test_seo.py` (59),
всего 695 (было 636). Версия 0.12.0.

### 2.12 [ ] Поиск: инфраструктура

**Цель.** Поиск по архиву: полнотекстовый и «похожие имена».

**Объём.**

- Новое приложение `apps/search` (в `INSTALLED_APPS`).
- Миграция с `CREATE EXTENSION IF NOT EXISTS pg_trgm` и GIN-индексами (`gin_trgm_ops`) для
  `Person`, `Team`, `Event`, `PersonName`.
- `SearchVectorField` + GIN-индекс для полнотекстового поиска (`tsvector`, конфигурация `russian`);
  заполнение через сигналы `post_save` (включая `PersonName`) и management-команду переиндексации.
- Приватность: в индекс не попадают скрытые фамилии — индексируется `public_name`, а не
  `display_name`/`last_name`.
- Тесты индексации и приватности индекса.

**Файлы:** `apps/search/__init__.py`, `apps/search/apps.py`, `apps/search/models.py`
(или поле в существующих моделях), `apps/search/signals.py`,
`apps/search/management/commands/search_reindex.py`, миграции, `config/settings.py`,
`tests/test_search_index.py`

**Критерии готовности.** Расширения и индексы создаются миграцией на PostgreSQL; после
`search_reindex` поиск находит объект по частичному слову и по варианту имени; скрытая фамилия
не находится поиском.

**Навыки:** koda-coder, semver-checker. **Размер:** M. **Semver:** minor.
