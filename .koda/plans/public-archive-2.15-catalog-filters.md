## 1. Цель подэтапа

Дать возможность найти нужное в растущем архиве: команды по городу и десятилетию
основания, события по году, типу и городу. Состояние фильтров живёт в query-параметрах:
ссылку можно сохранить и переслать, JavaScript не нужен.

Мастер-план (раздел 2.15) задаёт объём: `apps/catalog/filters.py`, панель фильтров
в шаблонах списков, состояние в URL, счётчики найденного, сброс фильтров, сортировка.
Модели и схема данных не меняются: все поля, по которым идёт отбор, уже есть
и проиндексированы (`Team.city`, `Team.founded_year`, `Event.year`, `Event.event_type`,
`Event.city`).

## 2. Решения, согласованные с владельцем (2026-10-19)

| # | Вопрос | Решение |
|---|---|---|
| 1 | Фильтр команд по времени | **Десятилетие основания** (`founded_year // 10 * 10`). Точный год дал бы длинный список и мало пользы; «команда известна в году» смешал бы «основана» с «активна» и потребовал бы соединений с фото, событиями и составом |
| 2 | Сортировка | **Два варианта на список.** Команды: по названию (по умолчанию) и по числу фотографий. События: сначала новые (по умолчанию) и сначала старые |
| 3 | Города | **Выпадающий список** из значений, которые есть в архиве. Свободный ввод дал бы пустую выдачу на опечатке и лишние варианты в URL |
| 4 | Индексация фильтрованных списков | **Индексируем** с `canonical` по валидным фильтрам: у отфильтрованной выдачи свой адрес, дублей нет. `noindex` остаётся только у страниц пагинации (уже работает в `page_meta`) |

### Что не делаем

- `django-filter` не подключаем: в проекте его нет, а объём фильтров — четыре селекта
  и два варианта сортировки. Своя функция в `filters.py` проще и не тянет зависимость.
- Счётчиков у каждого варианта фильтра («Москва — 12») не делаем: они требуют отдельного
  агрегирующего запроса на каждое поле и врут при комбинации фильтров (число зависит
  от остальных условий). Счётчик найденного — общий, из `page_obj.paginator.count`.
- Фильтров на `/years/` и `/people/` нет: списка людей в проекте нет осознанно
  (решение № 6 мастер-плана), а годы — уже сам фильтр.
- Сохранения фильтров в `session` нет: состояние живёт только в URL.

| Тесты | `tests/test_catalog_filters.py` |

### 3.2 Почему логика в отдельном модуле

Правило проекта: логика периодов состава живёт в `apps/catalog/roster.py`, а не в шаблоне
(подэтап 2.7). Фильтры — та же история: справочники вариантов, разбор параметров
и сборка `QueryDict` для `canonical` должны быть в одном месте, иначе шаблон начнёт
сравнивать строки, а представление — собирать адреса.

Шаблон получает готовую панель и только выводит её: ни одного `{% if request.GET.city %}`.

### 3.3 Справочники вариантов

Варианты считаются по **всей** публичной выборке (`public.published()`), а не по уже
отфильтрованной. Иначе после выбора года из списка городов исчезли бы города, в которых
в этом году ничего нет, и снять фильтр было бы нечем.

- **Города команд и событий** — `values_list("city", flat=True).distinct()`, пустые
  значения пропускаются. Варианты склеиваются по `strip().lower()`, подпись — первое
  встреченное написание; отбор идёт через `city__iexact`, поэтому `?city=москва`
  находит «Москва». Сортировка — по подписи.
- **Десятилетия команд** — из `founded_year` без пустых значений; подпись
  «1980-е» (`blocktranslate`-совместимая строка «%(start)s-е»), значение — начало
  десятилетия. От новых к старым. Отбор: `founded_year__gte=start, founded_year__lte=start+9`.
- **Годы событий** — из `Event.year`, от новых к старым.
- **Типы событий** — только те, что есть в опубликованных событиях; подпись берётся
  из `EventType(value).label`, то есть переводится вместе с интерфейсом.

Список вариантов — данные, а не разметка: `filters.py` возвращает
`{"value": ..., "label": ..., "selected": ...}`.

### 3.4 Разбор параметров

Невалидное значение считается **неприменённым фильтром**, а не пустой выдачей:
опечатка в ссылке не должна выглядеть как «ничего не найдено». То же правило, что
у `roster_year()` в подэтапе 2.7.

- `decade` — целое, входящее в список доступных десятилетий;
- `city` — строка, совпадающая с одним из вариантов (сравнение нормализованное);
- `year` — целое из списка годов событий;
- `type` — одно из значений `EventType`;
- `sort` — из допустимых для списка; неизвестное значение = сортировка по умолчанию.

### 3.5 Сборка выборки

`team_filters(request)` → `{"queryset": ..., "panel": ..., "query": QueryDict}`.

- Отбор применяется к `Team.public.published().annotate(photos_total=photos_count())` —
  аннотация уже нужна карточкам и сортировке по числу фото.
- Сортировка: `name` (по умолчанию) → `order_by("name")`; `photos` →
  `order_by("-photos_total", "name")`.
- `event_filters(request)`: `new` (по умолчанию) →
  `order_by(F("year").desc(nulls_last=True), "name")`; `old` →
  `order_by(F("year").asc(nulls_last=True), "name")`. `nulls_last` обязателен:
  в PostgreSQL при `DESC` события без года иначе оказались бы первыми.
- `query` — `QueryDict` только из валидных, реально применённых параметров (плюс `sort`,
  если он не по умолчанию). Нужен для `canonical`: мусор в адресе не должен попадать
  в карточку и в индекс поисковика.

### 3.6 Панель фильтров

`FilterPanel` — dataclass со списком полей и признаком «есть активные фильтры»:

```
FilterPanel(fields=[SelectField(...), ...], has_active=bool, reset_url=str)
```

- `SelectField`: `name`, `label`, `options`, `all_label` («Все города», «Все годы»,
  «Все типы», «Все десятилетия»), `selected`, `is_active`.
- Сортировка — тоже `SelectField` (имя `sort`), но в `has_active` не входит: порядок
  выдачи не сужает выборку, и «Сбросить фильтры» не должен сбрасывать сортировку.
- `reset_url` — адрес списка без параметров (сохраняем `sort`, если он выбран).
- `has_active` → шаблон показывает «Сбросить фильтры» и особое пустое состояние.

### 3.7 Canonical

`canonical_url(request)` сейчас берёт весь `request.GET` и выбрасывает только `page`.
Мусорный параметр (`?year=abc`, `?foo=bar`) попал бы в `canonical` и создал бы
бесконечное число «разных» адресов одной выдачи.

Изменение обратносовместимое: `canonical_url(request, query=None)` и
`page_meta(..., canonical_query=None)`; при `query=None` поведение прежнее. Списки
передают нормализованный `query` из `filters.py`. Существующий тест
`test_filters_are_kept_in_canonical` (страница команды, `?year=1994`) продолжает
работать: там `query` не передаётся.

## 7. Результат (2026-10-19)

Подэтап завершён, версия 0.16.0. Этап 2 (публичный архив) закрыт.

**Что сделано.** Списки `/teams/` и `/events/` получили фильтры и сортировку; состояние живёт
в query-параметрах, JavaScript не нужен.

- `apps/catalog/filters.py`: `team_filters()` (город, десятилетие основания) и
  `event_filters()` (год, тип, город), `FilterPanel` → `SelectField` для шаблона,
  нормализованный `QueryDict` для `canonical`.
- `apps/core/seo.py`: `canonical_url(request, query=None)` и
  `page_meta(..., canonical_query=None)` — при `None` поведение прежнее.
- `templates/catalog/partials/filters.html` и обновлённые списки: два пустых состояния,
  «Сбросить фильтры» при активных условиях.
- Стили `.filter-bar` с раскладкой в одну колонку на узком экране.
- Тесты `tests/test_catalog_filters.py` (48), всего 940 (было 892).

**Отклонения от плана.**

- Города-варианты сначала брали первое встреченное написание — тест показал, что это зависит
  от порядка строк в базе. Теперь подпись — самое частое написание, при равенстве первое
  по алфавиту (`collections.Counter`). Поведение предсказуемо и не зависит от порядка.
- Добавлены `select_related("sport")` не понадобились: карточки команд и событий вид спорта
  не выводят, лишний join в список не добавляли.
- Тесты canonical используют `html.unescape()`: Django экранирует `&` в атрибуте `href`,
  и сравнение с `urlencode()` падало на `&amp;`.

**Проверки.** `make lint` чист, `make test` — 940 тестов. Ручная проверка на демо-данных
(`manage.py shell` + тестовый клиент): `/teams/?city=Москва` — 1 команда из 4,
`/teams/?decade=1980` — 1, `/teams/?city=Москва&decade=1990` — 0 с сообщением «По выбранным
условиям ничего не найдено», `/events/?year=1994` — 1 событие, `/events/?sort=old` — порядок
меняется, `?city=Омск` (нет такого города) — фильтр не применяется, `canonical` без мусора.
Английская локаль: подписи панели переведены («City», «All decades», «1980s», «Apply»).

**Готча на будущее.** Значение фильтра, которого нет в справочнике, считается неприменённым.
Поэтому «ничего не найдено» получить можно только комбинацией валидных условий — при
тестировании пустой выдачи нужны два объекта, каждый из которых проходит одно условие
и не проходит другое.
