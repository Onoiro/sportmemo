# SportMemo — Этап 2.4: компонент галереи

Дата создания: 2026-10-11
Статус: **завершён** (2026-10-11, v0.4.0)
Мастер-план этапа: [`public-archive.md`](public-archive.md)
Предыдущий подэтап: [`public-archive-2.3-public-lists.md`](public-archive-2.3-public-lists.md)
Версия на старте: 0.3.0
Ветка: `feature/photo-gallery`

---

## 1. Зачем это

Списки готовы (2.3): `/teams/`, `/events/`, `/years/`, `/years/<год>/` отдают только
опубликованное и непубличное отсеивают. Но фотографии пока «немые»:

- карточка фото (`templates/photos/partials/card.html`) намеренно не кликабельна —
  страницы фото ещё нет;
- сетка фото продублирована в двух шаблонах (главная и год) вместо одного партиала;
- длинные годы листаются классической пагинацией: на страницу перезагружается вся разметка,
  хотя нужны только карточки.

2.4 закрывает три задачи:

1. **Один компонент галереи** для всех страниц: карточка + сетка + «показать ещё».
2. **Ленивая подгрузка следующей порции фото на htmx** с честным fallback без JS.
3. **Страница фотографии** `/photos/<pk>/` — «единица архива»: крупный просмотр, метаданные,
   люди на фото, источник, счётчик просмотров.

**Что не делаем в этом подэтапе:**

| Не делаем | Куда |
|---|---|
| Ссылки на команду, событие, человека со страницы фото (маршрутов нет) | 2.5, 2.6 |
| Плашка «не опубликовано» для автора и модератора | 2.5 |
| Метатеги, Open Graph, JSON-LD для фото | 2.10, 2.11 |
| Комментарии и жалобы под фото | 2.14 |
| Фильтры каталога (`?team=`, `?city=`) в UI | 2.15 |
| Загрузка фото пользователем | этап 3 |

## 2. Принятые решения

Согласовано с владельцем 2026-10-11 (ответы на вопросы плана):

| # | Вопрос | Решение |
|---|---|---|
| 1 | Как совместить «показать ещё» с пагинацией на `/years/<год>/` | **Заменить** классическую пагинацию галереей с кнопкой. Без JS кнопка — обычная ссылка `?page=N`: страница перезагружается и показывает следующую порцию. Списки команд, событий и годов пагинацию сохраняют (там карточки, а не фото) |
| 2 | Счётчик просмотров | Считаем при **каждом** открытии страницы, включая автора и модератора. Простейший вариант; защита от накрутки ботами — этап 4 |
| 3 | Объём страницы фото | Полная страница, но **без ссылок** на команду, событие и человека — этих маршрутов ещё нет (2.5/2.6). Названия выводятся текстом, как в карточках списков |

Решения мастер-плана, действующие здесь:

- Фото, привязанное к команде в `draft`, публикуется; название команды — текстом, без ссылки
  (решение № 3 мастер-плана).
- Черновик в публичном UI: виден автору и модератору, остальным — 404. Реализуется
  готовым `get_visible_or_404()` из 2.3, плашка «не опубликовано» — в 2.5.
- Счётчик просмотров — атомарный `update(views_count=F("views_count") + 1)`, **без записи
  в историю**: `django-simple-history` пишет запись только при `save()`.
- Пагинация фото — 24 на страницу (как в 2.3).
- Все строки интерфейса — через `gettext`, `make i18n` после добавления строк.

## 3. Что должно получиться на экране

**Главная (`/`).** Сетка последних 12 фото через общий партиал галереи. Карточки кликабельны.
Кнопки «показать ещё» нет: на главной одна страница.

**`/years/<год>/`.** Заголовок, сетка по 24 фото, под ней кнопка «Показать ещё».
По клику следующие 24 карточки дописываются в конец сетки без перезагрузки; когда фото
закончились, кнопка исчезает и появляется сообщение «Это все фотографии».
При выключенном JS кнопка — обычная ссылка `?page=2`.

**`/photos/<pk>/`.** Хлебные крошки Главная → Годы → 1994 → фото. Крупное изображение
(preview до 1280 px), справа/снизу — подпись, год со ссылкой на страницу года, команда
и событие текстом, источник (тип, издание, владелец), люди на фото с публичным именем,
ролью и позицией в кадре, строка «просмотров: N».

**Общее.** Всё открывается анонимно, работает в сепии и в тёмной теме, не разъезжается
на ~375 px. Карточка фото — одна ссылка на фото (без вложенных ссылок).

### 3. [x] Представления и маршруты `photos`: `photo_detail` и `grid`

- Навыки: koda-coder
- Файлы:
  - `apps/photos/views.py` (новый)
  - `apps/photos/urls.py` (новый)
  - `config/urls.py`
- Содержание:
  - `photo_detail(request, pk)`:
    1. `photo = get_visible_or_404(Photo, pk=pk, request=request)` — черновик, фото без
       подтверждённых прав, удалённое и слитое отсеиваются готовым хелпером; автору
       (`uploaded_by`) и модератору неопубликованное отдаётся.
    2. инкремент просмотров: `Photo.objects.filter(pk=photo.pk).update(
       views_count=F("views_count") + 1)` — атомарно, без `save()`, поэтому записи
       в `photo.history` не появляются. Затем `photo.views_count += 1` в памяти,
       чтобы не делать лишний `SELECT` (в шаблоне нужно актуальное число).
    3. выборки: `select_related("source", "team", "event")` и
       `prefetch_related("photo_persons__person")` — против N+1.
    4. контекст: `photo`, `photo_persons`, `breadcrumbs` (Главная → Годы → `<год>` → фото;
       если год не указан — Главная → фото).
  - `grid(request)`: `@require_GET`, htmx-фрагмент.
    - Базовый queryset — `visible_photos()` (та же точка входа, что у главной и года).
    - Фильтры: `year` (целое), `team` / `event` / `person` (slug; человек — через
      `photo_persons__person__slug`). Неизвестный slug даёт пустую выдачу естественным
      образом; нечисловой `year` — тоже пустая выдача (фрагмент не должен отдавать
      весь архив по опечатке в ссылке).
    - `paginate(request, qs, PHOTO_PAGE_SIZE)`, `select_related("team", "event")`.
    - Рендер `photos/partials/grid_items.html` (только карточки + контейнер кнопки).
  - `apps/photos/urls.py`: `app_name = "photos"`, маршруты
    `path("photos/<int:pk>/", views.photo_detail, name="photo_detail")` и
    `path("photos/grid/", views.grid, name="grid")` (`grid` объявлен первым: так связь
    «сначала фрагмент, потом объект» видна в URLconf, хотя `<int:pk>` строку не перехватит).
  - `config/urls.py`: `path("", include("apps.photos.urls"))`.
- Проверка: `manage.py check`; `/photos/<pk>/` отвечает 200 на демо-данных;
  `/photos/grid/?year=1994` — 200 и без `<html>` в ответе.

### 5. [x] Партиалы галереи: сетка и кнопка «показать ещё»

- Навыки: koda-coder
- Файлы:
  - `templates/photos/partials/grid.html` (новый)
  - `templates/photos/partials/grid_items.html` (новый)
- Содержание:
  - `grid.html`: `<div class="photo-gallery" id="photo-gallery">` → `<div class="photo-grid"
    id="photo-grid">` → `{% include "photos/partials/grid_items.html" %}`. Принимает
    `photos` (обязательно), `page_obj` (опционально — без него кнопки нет, как на главной)
    и `gallery_url` (опционально — задел для 2.5/2.6, где фильтр не лежит в `request.GET`).
  - `grid_items.html`: цикл карточек + контейнер
    `<div id="gallery-more" class="photo-gallery__more"{% if oob %} hx-swap-oob="outerHTML:#gallery-more"{% endif %}>`.
    Внутри при `page_obj.has_next()` — кнопка:
    `<a class="btn btn-outline-primary" href="{% querystring page=page_obj.next_page_number %}"
    hx-get="{% url 'photos:grid' %}{% querystring page=page_obj.next_page_number %}"
    hx-target="#photo-grid" hx-swap="beforeend">Показать ещё</a>` и спиннер
    `.htmx-indicator`. Если следующей страницы нет — пустой контейнер: кнопка исчезает
    после подгрузки последней порции. При переданном `gallery_url` — использовать его
    вместо `{% url 'photos:grid' %}`.
  - `{% querystring %}` (Django 5.2) сохраняет остальные query-параметры — фильтры
    передаются во фрагмент автоматически, без ручной сборки строки.
- Проверка: без JS `href` рабочая ссылка; с htmx — карточки дописываются (ручная проверка

## 5. Критерии готовности подэтапа

1. Сетка фото рендерится на главной и на `/years/<год>/` из одного партиала; карточки ведут
   на страницу фото.
2. «Показать ещё» подгружает следующую страницу без перезагрузки и исчезает в конце
   галереи; при выключенном JS видны первые 24 фото и работает обычная ссылка.
3. `/photos/<pk>/` открывается анонимно для опубликованного, отдаёт 404 черновику
   постороннему и открывается автору и модератору.
4. Просмотры растут атомарно и **не** создают записей в истории.
5. При `name_visibility=hidden` фамилия не появляется в HTML страницы фото.
6. `make lint && make test` зелёные, `makemigrations --check` чист; обе темы и ~375 px
   не разъезжаются.
7. README, KODA.md, AGENTS.md описывают новое состояние; версия 0.4.0, `uv.lock`
   синхронизирован.

| Кнопка не исчезает в конце галереи | Фрагмент отдаёт пустой контейнер с `hx-swap-oob="outerHTML:#gallery-more"`; тест на HTML фрагмента + ручная проверка |
| Замена пагинации на году ломает тесты 2.3 | `page_obj` остаётся в контексте; тесты проверяют контекст, а не блок пагинации |
| N+1 на бейджах команды и события в карточке | `select_related("team", "event")` в представлениях галереи |
| Счётчик просмотров накручивается автором и ботами | Осознанное решение: простейший вариант, защита — этап 4 |
| `update()` не обновляет объект в памяти | После инкремента `photo.views_count += 1` — без лишнего `SELECT` |
| `makemessages` ставит `fuzzy` на новые строки | Проверка fuzzy-блоков после `make i18n` |
| htmx-фрагмент «протекает» в поисковики | Фрагмент отдаётся только по ссылке галереи; `noindex` для пагинации — в 2.10 |
