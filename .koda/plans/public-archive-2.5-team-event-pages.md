# SportMemo — Этап 2.5: страницы команды и события

Дата создания: 2026-10-11
Статус: **завершён**
Мастер-план этапа: [`public-archive.md`](public-archive.md)
Предыдущий подэтап: [`public-archive-2.4-photo-gallery.md`](public-archive-2.4-photo-gallery.md)
Версия на старте: 0.4.0
Ветка: `feature/team-event-pages`

---

## 1. Зачем это

Списки готовы (2.3), галерея и страница фото — тоже (2.4). Но карточки команд
и событий в списках намеренно не кликабельны: страниц, на которые они должны вести,
ещё нет. Из-за этого архив «плоский» — с фото нельзя перейти ни к команде, ни к событию.

2.5 даёт две «страницы-визитки», на которые ведут ссылки из списков, галереи и мессенджеров:

1. **`/teams/<slug>/`** — команда: эмблема, город, год основания, описание, атрибуты,
   фотографии команды, её события, краткий состав.
2. **`/events/<slug>/`** — событие: тип, даты, место, описание, атрибуты,
   команды-участники с результатами, фотографии события.

Заодно закрываются два долга предыдущих подэтапов: плашка «не опубликовано» для автора
и модератора (отложена из 2.4) и блок «События года» на `/years/<год>/` (отложен из 2.3).

**Что не делаем в этом подэтапе:**

| Не делаем | Куда |
|---|---|
| Страница человека `/people/<slug>/` и ссылки на людей | 2.6 |
| Полный «состав по годам» (`/teams/<slug>/roster/`) и кнопка к нему | 2.7 |
| Метатеги, Open Graph, JSON-LD | 2.10, 2.11 |
| Комментарии и жалобы под командами и событиями | 2.14 |
| Фильтры каталога (`?city=`, `?year=`) | 2.15 |

## 2. Принятые решения

Согласовано с владельцем 2026-10-11 (ответы на вопросы плана).

| # | Вопрос | Решение |
|---|---|---|
| В-1 | Кнопка «состав по годам» (маршрут появится в 2.7) | **Не показывать.** Обещание «скоро» в интерфейсе хуже, чем его отсутствие: на странице команды только краткий состав |
| В-2 | Сколько человек в кратком составе | **12**, дальше — полный состав в 2.7 |
| В-3 | Что делать с `attributes` | Служебный ключ `demo` не показываем; известные ключи переводим через `gettext`; неизвестные выводим как есть |
| В-4 | Формат дат события | Только **месяц и год**, без чисел: «июль 1980», «июнь — июль 1988», «июль 1988 — август 1989», «1980» (если есть только год), «дата не указана» |
| В-5 | Фото на детальных страницах | **Галерея с «показать ещё»** — готовый компонент из 2.4, фильтры `team`/`event` уже поддерживаются |
| В-6 | События года на `/years/<год>/` | Блок карточек **без пагинации**: событий в году обычно немного |

Решения мастер-плана, действующие здесь:

- Черновик в публичном UI: виден автору и модератору (с плашкой «не опубликовано»),
  остальным — 404. Работает готовый `get_visible_or_404()` из 2.3.
- Команда или событие в `draft` показываются **текстом, без ссылки** — то же правило,
  что для фото и команды (решение № 3 мастер-плана).
- Namespace `catalog` обязателен: он уже зашит в `SlugModel.url_name`
  (`Team.url_name = "catalog:team_detail"`, `Event.url_name = "catalog:event_detail"`).
  Модели менять не нужно.
- Все строки интерфейса — через `gettext`, `make i18n` после добавления строк.

**Отказ от лишнего.** В предварительном плане был пункт «миксин публичной видимости
в core + подключение в `Team` и `Event`». Он не нужен: проверка уже живёт в
`get_visible_or_404()` — это единственная точка правила. Второй механизм нарушил бы
принцип «правило отсева должно быть в одном месте».

## 3. Что должно получиться на экране

**`/teams/sokoly/`.** Хлебные крошки Главная → Команды → «Соколы». Шапка: эмблема (если
загружена), название, город, год основания, вид спорта. Ниже — описание, список атрибутов,
«Фотографии команды» (галерея с «показать ещё»), «События» (карточки событий, от новых
к старым), «Состав» (до 12 человек: публичное имя, роль, годы, амплуа).

**`/events/chempionat-rossii-1994/`.** Хлебные крошки Главная → События → «Чемпионат России».
Шапка: тип события бейджем, название, «май 1994», «Екатеринбург, Россия». Ниже — описание,
атрибуты («Этап: финал», «Результат: 1 место», «Команд: 6»), «Команды-участники»
(название командой-ссылкой, если опубликована, иначе текстом + результат), «Фотографии
события» (галерея).

**`/years/1994/`.** Под галереей появляется блок «События года» — карточки событий 1994 года.

**Черновик.** Автор и модератор видят страницу с плашкой «Не опубликовано» и пояснением,
что её видно только им. Остальные получают 404.

**Общее.** Всё открывается анонимно, работает в сепии и в тёмной теме, не разъезжается
на ~375 px. Пустые блоки (нет фото, нет событий, нет состава, нет описания) страницу
не ломают и не оставляют пустых заголовков.

### 2. [x] `Event.date_label` — форматирование дат события

- Навыки: koda-coder
- Файлы:
  - `apps/catalog/models.py`
- Содержание: свойство `Event.date_label` — строка для интерфейса, без чисел дня:

  | Данные | Вывод |
  |---|---|
  | `date_from` и `date_to`, совпадают месяц и год | «июль 1980» |
  | разные месяцы одного года | «июнь — июль 1988» |
  | разные годы | «июль 1988 — август 1989» |
  | только `date_from` | «июль 1980» |
  | дат нет, есть `year` | «1980» |
  | ничего | «дата не указана» |

  Месяц форматируется через `django.utils.formats.date_format(value, "F Y")` —
  название месяца берётся из активной локали («июль» / «July»), отдельные строки
  для месяцев не нужны. Логика живёт в модели, а не в шаблоне: тем же свойством
  воспользуются карточки событий и 2.15.
- Проверка: `uv run python -c` со всеми шестью вариантами; миграция не нужна
  (это свойство, а не поле).

### 3. [x] Представления и маршруты `catalog:team_detail`, `catalog:event_detail`

- Навыки: koda-coder
- Файлы:
  - `apps/catalog/views.py`
  - `apps/catalog/urls.py`
- Содержание:
  - `team_detail(request, slug)`:
    1. `team = get_visible_or_404(Team, request=request, slug=slug)` — черновик,
       скрытое, отклонённое, удалённое и слитое отсеиваются готовым хелпером.
    2. фото команды: `visible_photos().filter(team=team).select_related("team", "event")`,
       `paginate(request, qs.order_by(*PHOTO_ORDERING), PHOTO_PAGE_SIZE)`;
       в контекст — `gallery_query=QueryDict(f"team={slug}")` (фильтр не лежит
       в `request.GET` — задел из 2.4).
    3. события команды: `Event.public.published().filter(event_teams__team=team)`,
       порядок `F("year").desc(nulls_last=True), "name"` (иначе события без года
       в PostgreSQL окажутся первыми).
    4. состав: `team.memberships.filter(person__in=Person.public.published())`
       с `select_related("person")`, порядок `F("year_from").desc(nulls_last=True)`,
       срез `[:TEAM_ROSTER_PREVIEW]`. Фильтр по `Person.public.published()` — правило
       проекта: люди-черновики в публичную выдачу не попадают.
    5. `attribute_items` — из `team.attributes` (см. шаг 4).
    6. `breadcrumbs`: Главная → Команды → название.
  - `event_detail(request, slug)`:
    1. `get_visible_or_404(Event, request=request, slug=slug)`.
    2. фото события: `visible_photos().filter(event=event)`, `gallery_query`
       с `event={slug}`.
    3. команды-участники: `event.event_teams.select_related("team")` — порядок модели
       (`event`, `team`). Команда-черновик остаётся в списке: название выводится
       текстом, ссылки на неё не будет (правило мастер-плана).
    4. `attribute_items` — из `event.attributes`.
    5. `breadcrumbs`: Главная → События → название.
  - Константа `TEAM_ROSTER_PREVIEW = 12`.
  - `apps/catalog/urls.py`: `path("teams/<slug:slug>/", ...)` и
    `path("events/<slug:slug>/", ...)` **после** списков (`teams/` и `events/`),
    иначе `<slug>` перехватит их.
- Проверка: `manage.py check`; на демо-данных `/teams/sokoly/` и
  `/events/chempionat-rossii-1994/` отвечают 200; `/teams/` и `/events/` по-прежнему
  отдают списки.

## 5. Критерии готовности подэтапа

1. `/teams/<slug>/` и `/events/<slug>/` открываются анонимно, отдают 404 черновику
   постороннему и открываются автору и модератору с плашкой «Не опубликовано».
2. Фотографии, события команды, состав, команды-участники и атрибуты выводятся;
   пустые блоки не ломают вёрстку и не оставляют пустых заголовков.
3. Ссылки на неопубликованные команды и события не создаются нигде: ни в списках,
   ни на детальных страницах, ни на странице фото.
4. В составе нет людей-черновиков; фамилия при `name_visibility=hidden` не появляется
   в HTML.

## 6. Риски и заметки

| Риск | Как учитываем |
|---|---|
| Маршрут `teams/<slug>/` перехватит `teams/` | Детальные маршруты объявляются **после** списков |
| `Person.url_name` уже указывает на `catalog:person_detail`, которого ещё нет | Ссылок на людей в шаблонах 2.5 нет — только `public_name` текстом. Иначе `reverse()` упадёт с `NoReverseMatch` |
| События без года при `DESC` в PostgreSQL окажутся первыми | `F("year").desc(nulls_last=True)` — как в 2.3 |
| Люди без года в составе (`year_from` пуст) | `F("year_from").desc(nulls_last=True)`; отдельный блок «год не указан» — в 2.7 |
| Название черновой команды утекает на странице события | Осознанно: то же решение мастер-плана, что для фото (№ 3) — текст без ссылки |
| Две галереи на одной странице сломают `#gallery-more` | Галерея на странице одна (фото команды или фото события) |
| `attributes` содержат служебные и неизвестные ключи | Служебный `demo` скрыт; известные переведены; неизвестные выводятся как есть, без падения |
| `makemessages` ставит `fuzzy` на новые строки | Проверка fuzzy-блоков после `make i18n` |
| Черновик утекает в поисковики | `noindex` для черновиков — в 2.10 |

Отклонения от плана и решения по ходу работы:

1. **Появился конвертер URL `uslug`** (`apps/core/converters.py`). Плана на него не было,
   но стандартный `<slug:...>` пропускает только ASCII, а slug'и хранятся с
   `allow_unicode=True` (`slugify(..., allow_unicode=True)`): `reverse()` падал бы
   с `NoReverseMatch` на «соколы». Конвертер регистрируется в `CoreConfig.ready()`.

   счётчика фото теперь использует и страница года, а своя копия в `catalog/views.py`
   разошлась бы с ней.

   бы адрес на кириллице и `&` в slug'е.
4. **`require_GET` на детальных представлениях** — как на странице фото.
5. **`publish_with_attributes()` в `tests/utils.py`**: `publish()` сохраняет только поля
   модерации (`update_fields`), поэтому `attributes`, записанные перед публикацией,
   в базу не попадали.
