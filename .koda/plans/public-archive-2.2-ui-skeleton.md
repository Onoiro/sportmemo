# SportMemo — Этап 2.2: каркас публичного UI

Дата создания: 2026-10-11
Статус: **завершён** (v0.2.0)
Мастер-план этапа: [`public-archive.md`](public-archive.md)
Предыдущий подэтап: [`public-archive-2.1-seed-demo.md`](public-archive-2.1-seed-demo.md)
Версия на старте: 0.1.2
Ветка: `feature/ui-skeleton`

---

## 1. Зачем это

Этап 1 закончился схемой данных и админкой: публичного UI нет, корневой URL отдаёт 404.
Подэтап 2.1 наполнил базу вымышленным архивом — есть что показывать, но негде.

2.2 даёт **каркас**: общий layout, тему, навигацию и главную страницу. Всё остальное
в этапе 2 (списки, страницы-детали, галерея, поиск, регистрация) — это «наполнение» этого
каркаса. Пока каркаса нет, каждую страницу пришлось бы верстать с нуля.

**Что не делаем:** списки и страницы-детали (2.3–2.7), компонент галереи с «показать ещё»
(2.4), метатеги и SEO (2.10–2.11), поиск (2.12–2.13), регистрацию (2.8).

## 2. Принятые решения

Из мастер-плана этапа (решения № 1, 4, 5, 6) и уточнений этой сессии:

| # | Вопрос | Решение |
|---|---|---|
| 1 | Фронтенд-зависимости | Локально в `static/vendor/`. Версии на 2026-10-11: Bootstrap **5.3.8**, Bootstrap Icons **1.13.2**, htmx **2.0.11**, Alpine.js **3.17.4**. Доступность CDN проверена |
| 2 | Ссылки на разделы, которых ещё нет (**В-1**) | **Вариант (а): заглушки.** В 2.2 создаются маршруты `catalog:team_list`, `catalog:event_list`, `core:year_list` и `core:search` с одним общим представлением-заглушкой («раздел появится позже»). В 2.3 и 2.13 представления заменяются настоящими. Навигация кликается уже сейчас, каркас проверяется в браузере целиком |
| 3 | Форма поиска в navbar и на главной (**В-2**) | Делаем в 2.2. Отправляет GET на `/search/` (пока заглушка), пустой запрос не отправляется |
| 4 | Счётчик «лет» (**В-3**) | «Число лет» = количество уникальных `Photo.year` среди видимых фото. Не диапазон |
| 5 | Режимы темы (**В-4**) | Два: **сепия** (светлая, по умолчанию) и **тёмная**. Отдельной «чистой белой» нет |
| 6 | Публичные выборки | Часть правила «публичных выборок» добавляется уже в 2.2 (см. шаг 2) — иначе главная покажет черновики и фото без прав. Остальное (`get_visible_or_404`) — в 2.3 |
| 7 | Тема: как устроено | Bootstrap понимает только `light`/`dark`, поэтому: на `<html>` всегда `data-bs-theme`, а сепия — класс `theme-sepia`, переопределяющий переменные Bootstrap. В светлом режиме класс есть всегда, в тёмном — нет |

### Отклонения от мастер-плана

| Что | Почему |
|---|---|
| `templates/partials/pagination.html` перенесён в 2.3 | В 2.2 пагинации негде применяться: первый список появляется в 2.3. Писать партиал «на глаз» — работа в стол |
| Маршрут поиска временно называется `core:search`, а не `search:index` | Приложение `apps/search` создаётся в 2.12. В 2.13 маршрут переедет в namespace `search`, ссылка в navbar обновится одной строкой |

## 3. Что должно получиться на экране

**Навигация (navbar).** Слева — «SportMemo» (ссылка на главную). В центре/справа: «Команды»,
«События», «Годы» (пока заглушки), форма поиска, переключатель темы, вход/меню пользователя
(«Войти» → `/accounts/login/` из allauth; профиль — 2.8).

**Главная (`/`).** Крупный заголовок в архивном serif-стиле, строка поиска, блок статистики
(команд / фото / лет), две плитки-входа «Команды» и «Годы», ниже — сетка последних добавленных
фото с годом и подписью. Если архива нет — понятное пустое состояние, а не пустая страница.

**Тема.** Тёплая бумажная сепия по умолчанию; тёмный вариант — с тёплым, а не синеватым фоном.
Заголовки — serif-стек системных шрифтов (Georgia / DejaVu Serif), текст — системный sans.
Внешние шрифты не грузим. Выбор запоминается в `localStorage`, при первом визите берётся
`prefers-color-scheme`. Мигания при загрузке быть не должно.

**Страницы ошибок.** 404 и 500 в общем оформлении, со ссылкой на главную.

### Границы: что в 2.2 намеренно не работает

- **Карточки фото не кликабельны.** Страница фото появляется в 2.4, до этого ссылка вела бы
  в никуда.
- **`get_absolute_url()` не вызываем.** `Team`/`Person`/`Event` возвращают адреса маршрутов
  `catalog:*_detail`, которых до 2.5–2.6 не существует — это `NoReverseMatch` в шаблоне.
- Страницы-заглушки показывают заголовок раздела и пояснение, что он появится позже.

## 5. Критерии готовности подэтапа

1. Главная открывается анонимно и показывает статистику и последние фото; черновики, скрытые
   и фото без подтверждённых прав в выдачу не попадают.
2. Тема переключается и запоминается между визитами; мигания при загрузке нет; тёмный режим
   читаем.
3. Все ссылки в navbar работают: разделы ведут на заглушки, поиск — на заглушку с `?q=`.
4. 404 отдаёт оформленную страницу; 500 рендерится из `templates/500.html`.
5. Вёрстка не разъезжается на мобильном разрешении (проверка в браузере на ширине ~375 px).
6. `make lint && make test` зелёные; `makemigrations --check` чист.
7. README, KODA.md и AGENTS.md описывают новое состояние; версия 0.2.0, `uv.lock`
   синхронизирован.

## 6. Риски и заметки

| Риск | Как учитываем |
|---|---|
| `{% url %}` на несуществующий маршрут ломает страницу | Заглушки создаются в том же шаге, что и навигация; `get_absolute_url()` в шаблонах 2.2 не вызывается |
| `NoReverseMatch` на `catalog:*_detail` | Тест на рендер главной и navbar ловит это сразу |
| Шрифты иконок не подхватятся | Шрифты кладутся рядом с CSS иконок, путь относительный; проверка в браузере (шаг 11) |
| Мигание темы при загрузке | Инлайн-скрипт в `<head>` до подключения CSS-отрисовки; тест проверяет его позицию |
| `CompressedManifestStaticFilesStorage` требует `collectstatic` | В тестах conftest уже подменяет бэкенд статики; в браузере проверяем через `make run` (DEBUG=True — манифест не используется) |
| `makemessages` ставит `fuzzy` на новые строки | Явная проверка fuzzy-блоков после `make i18n` (грабли из проекта TaskMan) |
| 404/500 в тестах не воспроизводятся | `override_settings(DEBUG=False)` + `ALLOWED_HOSTS=["testserver"]`; для 500 — `raise_request_exception = False` и падающее представление |
| Партиал `pagination.html` останется мёртвым кодом | Перенесён в 2.3 (см. «Отклонения») |
| Vendor-библиотеки в git раздувают репозиторий | ~1 МБ; это цена работы без CDN и без интернета — решение № 1 мастер-плана |
