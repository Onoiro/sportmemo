# SportMemo — Этап 2.3: публичные выборки и списки

Дата создания: 2026-10-11
Статус: **завершён**
Мастер-план этапа: [`public-archive.md`](public-archive.md)
Предыдущий подэтап: [`public-archive-2.2-ui-skeleton.md`](public-archive-2.2-ui-skeleton.md)
Версия на старте: 0.2.0
Ветка: `feature/public-lists`

---

## 1. Зачем это

Каркас UI готов (2.2), демо-архив есть (2.1), но все разделы — заглушки: «Команды»,
«События» и «Годы» показывают одну страницу «Раздел в разработке».

2.3 закрывает две задачи:

1. **Единый способ отдавать наружу только опубликованное.** Правило проекта «публичные
   выборки идут через `public`» уже работает для `published()`/`visible()` (сделано в 2.2).
   Не хватает хелпера для страниц-деталей: `get_visible_or_404()` — черновик должен отдавать
   404 постороннему, но открываться автору и модератору с плашкой «не опубликовано».
2. **Первые настоящие страницы-списки:** `/teams/`, `/events/`, `/years/`, `/years/<год>/`
   с пагинацией, сортировкой и пустыми состояниями. Они же — «полигон» для проверки правил
   отсева: черновики, скрытые, отклонённые, удалённые, слитые и фото без подтверждённых прав.

**Что не делаем в этом подэтапе:**

| Не делаем | Куда |
|---|---|
| Страницы-детали команды и события | 2.5 |
| Страницы человека и фото | 2.6 |
| Компонент галереи и «показать ещё» на htmx | 2.4 |
| Плашка «не опубликовано» в UI (хелпер только готовится) | 2.5 |
| Пользовательские фильтры каталога | 2.15 |
| Настоящий поиск (`/search/` остаётся заглушкой) | 2.13 |

## 2. Принятые решения

Уточнения этой сессии (согласованы с владельцем 2026-10-11):

| # | Вопрос | Решение |
|---|---|---|
| 1 | Что показывает `/years/<год>/` | **Вариант А:** только фотографии этого года. События года добавим в 2.5, когда появится страница события (иначе некуда вести ссылку) |
| 2 | Из чего строится список `/years/` | Из **видимых фото** (`Photo.year`), с числом фото на год. Иначе список лет разойдётся со счётчиком «лет в архиве» на главной |
| 3 | Кликабельность карточек | Карточки команды и события — **без ссылок**: детальные страницы появляются в 2.5. Ссылки на фото — в 2.4/2.6. Так же, как карточка фото в 2.2 |
| 4 | Пагинация | 24 команды, 20 событий, 24 фото на страницу. Список годов — без пагинации (их десятки) |

Решения мастер-плана, действующие здесь:

- URL-схема: `/teams/`, `/events/`, `/years/`, `/years/<int:year>/` (см. § 3.1 мастер-плана).
- Namespace `catalog` обязателен: он зашит в `SlugModel.url_name` (`catalog:team_detail`).
  `get_absolute_url()` в шаблонах 2.3 **не вызывается** — маршрутов `*_detail` ещё нет.
- Счётчик просмотров, метатеги, JSON-LD — не в этом подэтапе.

## 3. Что должно получиться на экране

**`/teams/`.** Заголовок «Команды», счётчик найденного, сетка карточек: название, город,
год основания, число фотографий, описание в две строки. Сортировка по названию. Пагинация.
Пустое состояние: «В архиве пока нет команд».

**`/events/`.** Заголовок «События», сетка карточек: название, тип (бейдж), год, город,
число фотографий. Сортировка от новых к старым, события без года — в конце. Пагинация.

**`/years/`.** Список годов от новых к старым: год крупно, рядом число фотографий, ссылка
на `/years/<год>/`. Без пагинации. Пустое состояние.

**`/years/<год>/`.** Заголовок «1994 год», сетка видимых фото этого года (карточка из
`templates/photos/partials/card.html`), пагинация по 24. Хлебные крошки: Главная → Годы → 1994.
Несуществующий или «пустой» год — 404.

**Общее.** Все страницы открываются анонимно, работают в обеих темах, не разъезжаются
на мобильном разрешении.

### 2. [x] Хелперы публичных выборок: `apps/core/shortcuts.py`

- Навыки: koda-coder
- Файлы:
  - `apps/core/shortcuts.py`
  - `apps/core/views.py`
- Содержание:
  - `visible_photos()` и `archive_stats()` переезжают из `apps/core/views.py`
    в `apps/core/shortcuts.py` — их теперь используют и главная, и списки.
    `apps/core/views.py` импортирует их оттуда (константа `HOME_PHOTO_LIMIT` остаётся
    в `views.py`: она описывает главную, а не общее правило).
  - `paginate(request, queryset, per_page)` — единая точка пагинации: возвращает `Page`
    из `django.core.paginator.Paginator`; нечисловой или отрицательный `page` не роняет
    страницу (Paginator сам отдаёт первую/последнюю).
  - `get_visible_or_404(model, *, request=None, **lookup)`:
    1. объект берётся из `model.public` (без удалённых и слитых), иначе `Http404`;
    2. объект «виден публично», если `is_published` и — когда у модели есть поле
       `rights_confirmed` — права подтверждены (правило «фото без прав не публикуется»);
    3. если публично не виден, объект отдаётся только автору (`created_by` или
       `uploaded_by` совпадает с `request.user`) и модератору (`user.is_moderator`),
       остальным — `Http404`.
  - `shortcuts.py` не импортирует модели приложений: работает через переданный `model`,
    чтобы не создавать циклов между `core` и `catalog`/`photos`.
- Проверка: `uv run python -c "from apps.core import shortcuts"` без ошибок;
  существующие тесты `tests/test_home.py` и `tests/test_public_queries.py` зелёные
  (поведение не изменилось).

## 5. Критерии готовности подэтапа

1. `/teams/`, `/events/`, `/years/`, `/years/<год>/` открываются анонимно и показывают
   настоящие данные демо-архива.
2. В списках нет черновиков, скрытых, отклонённых, удалённых и слитых объектов; фото
   без подтверждённых прав не показывается ни в одном списке.
3. `get_visible_or_404` отдаёт черновик автору и модератору, остальным — 404; покрыт
   тестами на каждый случай.
4. Пагинация работает и не ломается на `?page=abc`/`?page=999`; при одной странице блок
   пагинации не рендерится.
5. Пустые состояния понятны; вёрстка не разъезжается на ~375 px, обе темы читаемы.
6. `make lint && make test` зелёные, `makemigrations --check` чист.
7. README, KODA.md, AGENTS.md описывают новое состояние; версия 0.3.0, `uv.lock`
   синхронизирован.

## 6. Риски и заметки

| Риск | Как учитываем |
|---|---|
| `get_absolute_url()` на несуществующий маршрут | В шаблонах 2.3 не вызывается; карточки без ссылок |
| Пустой год в PostgreSQL при `DESC` идёт первым | Явный `F("year").desc(nulls_last=True)` |
| `Count` по обратной связи размножает строки | `distinct=True` в аннотации |
| Циклический импорт `core` ↔ `catalog` | `shortcuts.py` работает через переданный `model`, модели приложений не импортирует |
| `makemessages` ставит `fuzzy` на новые строки | Проверка fuzzy-блоков после `make i18n` |
| Разъезд «лет в архиве» на главной и списка `/years/` | Оба считаются от `visible_photos()` — один источник |
| Тесты заглушек начнут падать после замены представлений | `PLACEHOLDERS` в `tests/test_home.py` правится в том же шаге 10 |
| Партиал пагинации теряет query-параметры | `querystring` без `page` готовит представление; тест на `?page=2` |
