**Дополнение к 2.9 (2026-10-12).** Дубликаты названий команд не блокируются: форма
предупреждает и просит подтверждение, а настоящие дубликаты сливает модератор. Правка
опубликованной команды статус не сбрасывает (открытый вопрос № 1 мастер-плана закрыт).
Вид спорта в форме не показывается — берётся `default_sport()`.

**Почему 2.8 разделён на две части (2026-10-11).** Изначально подэтап планировался одним
куском: 16+ новых шаблонов, переопределение 8 форм allauth, локализация писем и сценарные
тесты. Это две разные пользовательские истории — «войти в аккаунт» и «мой аккаунт», — и каждая
проверяется в браузере отдельно. Разрез по сценариям даёт две проверяемые точки и два небольших
диффа; часть 2.8а закрывает задачу P2-7 целиком.

**Заявка «это я» (P2-7б) — отложена.** Полный сценарий: новая модель `PersonClaim`, миграция,
форма «это я» на странице человека, список заявок и действие модератора в админке. В 2.8
не делается: объём несопоставим с остальной частью подэтапа, а без модерации заявка
небезопасна — любой мог бы «присвоить» чужую страницу. В профиле (2.8б) есть только ссылка
на уже связанного человека; кнопки «Это я» нет, пока сценарий не реализован.

**Соредакторы команды (P2-14, новая).** Сейчас команду правит только её создатель и модератор.
Реальный случай: команду завёл один человек, а дополнить её хотят другие — например, игроки
той же команды. Нужен механизм заявок «я в этой команде» (`TeamClaim`) с подтверждением
модератором — симметрично отложенной заявке «это я». Без модерации давать права нельзя:
архивные данные легко испортить.

**Удаление своей команды (P2-15, новая).** Автор не может убрать созданную команду.
Нужна политика: что делать с фото и составом, привязанными к команде, — мягкое удаление
(`soft_delete`) с записью причины выглядит правильным, но решать владельцу. Приоритет P2.

| ID | Идея |
|---|---|
| I-1 | «Лента времени» архива: события по годам с фото |
| I-2 | Карточки «персона» с автоматически собранными фото и статистикой |
| I-3 | Экспорт архива команды в PDF (книга памяти) |
| I-4 | Связь с существующими базами (например, статистика турниров) |
| I-5 | Мультиспортный UI и приглашение евангелистов по другим видам спорта |
| I-6 | Публичный API для исследователей (после стабилизации схемы) |
| I-7 | Импорт из соцсетей и мессенджеров (сохранённые фото из чатов команд) |
| I-8 | Отдельная страница «состав команды по годам» (`/teams/<slug>/roster/`): группировка по годам, фильтр по роли, навигация по годам. Отложено: архив наполняется по чужим альбомам, и на старте состав за конкретный год заведомо неполный — страница читалась бы как полный список. В 2.7 (v0.7.0) сделана честная замена: фильтр по годам на странице команды. Вернуться, когда составов наберётся достаточно, чтобы группировка стала осмысленной |
| I-9 | Клуб и его команды. Реальный случай: клуб «Русстар» — это несколько команд (высшая лига, любительская, детские разных возрастов), и таких клубов много. Пока команды заводятся отдельными записями с уточнением в названии («Русстар-2», «Русстар (юноши 1992 г. р.)»), подсказка об этом есть в форме создания (2.9). Структурное решение: nullable-поле `Team.parent` (клуб-контейнер без фото и состава) + блок «Другие команды клуба» + страница клуба. Миграция не требует переноса данных — команды уже заведены отдельно. Делать, когда появится первый настоящий клуб с несколькими командами |
| I-10 | Соредакторы команды: заявки «я в этой команде» (`TeamClaim`) с подтверждением модератором (подробнее — P2-14) |
| I-11 | Подсветка совпадений в выдаче поиска (`ts_headline` / `SearchHeadline`): найденный фрагмент оборачивается в `<mark>`, и сразу видно, почему объект попал в выдачу. **Под вопросом** — отложено при планировании 2.13 (2026-10-16). Три сложности: (а) `ts_headline` возвращает HTML без экранирования, поэтому название вида `</script><script>alert(1)</script>` разорвало бы страницу — нужна схема «служебные маркеры → `escape()` → замена маркеров на `<mark>`» и тест на экранирование; (б) `Person.public_name` — свойство Python, а не колонка в БД, подсветить его нельзя, а подсвечивать `last_name` нельзя по приватности (раскрыло бы скрытую фамилию) — люди останутся без подсветки; (в) карточки (`catalog/partials/team_card.html`, `event_card.html`, `photos/partials/card.html`) переиспользуются в списках, где подсветки нет, — понадобится необязательная переменная с готовым HTML (двухрежимные карточки) |
